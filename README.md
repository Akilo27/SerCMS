# SerCMS

**SerCMS** — модульная система управления веб-проектом на базе Django. Она объединяет инструменты для создания и администрирования сайта, управления интернет-магазином и обработки связанных бизнес-процессов в одном приложении.

Проект рассчитан на развитие сайтов и онлайн-сервисов, которым недостаточно обычной CMS: помимо управления страницами и контентом, в системе предусмотрены отдельные модули для каталога товаров, заказов, платежей, доставки, работы с клиентами и внутренних процессов.

> Репозиторий содержит развиваемый проект. Наличие модуля в исходном коде не означает, что все его сценарии уже полностью завершены или готовы к промышленной эксплуатации.

## Назначение проекта

Основная задача SerCMS — предоставить единую основу для разработки и управления функциональным веб-сайтом или интернет-магазином.

Система объединяет несколько направлений:

- **Управление сайтом:** страницы, общие настройки и контент.
- **Электронная коммерция:** каталог, товары, корзина и связанные операции магазина.
- **Работа с клиентами:** инструменты CRM и пользовательские профили.
- **Обработка заказов:** интеграция процессов оплаты и доставки.
- **Взаимодействие с пользователями:** чат, отзывы и модерация.
- **Внутренние процессы:** документация, HR-инструменты и показатели эффективности.
- **Интеграции:** импорт данных и программный API для взаимодействия с другими системами.

Таким образом, SerCMS выступает не просто редактором страниц, а расширяемой платформой для управления сайтом и сопутствующими операциями.

│   ├── documentation/       # Документация
│   ├── development/          # Дополнительные инструменты

## Технологический стек

- **Python 3.12** — основной язык приложения.
- **Django 5.2** — веб-фреймворк и основа серверной части.
- **Django REST Framework** — создание REST API.
- **Simple JWT** — работа с JWT-токенами.
- **PostgreSQL 14** — реляционная база данных в Docker-окружении.
- **Redis** — брокер и вспомогательное хранилище для фоновых задач.
- **Celery** — выполнение фоновых и периодических задач.
- **Django Channels и Daphne** — ASGI и поддержка асинхронных сценариев.
- **Docker Compose** — запуск приложения и инфраструктурных сервисов.

Дополнительные библиотеки используются для импорта и обработки таблиц, локализации, изображений, административного интерфейса и других задач. Полный перечень зависимостей находится в [requirements.txt](requirements.txt).

## Запуск через Docker Compose

### Требования

Перед запуском установите:

- Docker;
- Docker Compose v2 (команда `docker compose`).

### Подготовка окружения

1. Склонируйте репозиторий:

   ```bash
   git clone https://github.com/Akilo27/SerCMS.git
   cd SerCMS
   ```

2. Подготовьте файл `.env` в корне проекта. В нём должны быть заданы параметры PostgreSQL и Django, согласованные с `docker-compose.yaml` и настройками приложения.

   **Важно:** имеющийся `env.tmpl` перед использованием необходимо проверить и очистить от любых действующих паролей, ключей и адресов сторонних сервисов. Не используйте опубликованные в репозитории значения секретов.

3. Проверьте конфигурацию Docker Compose:

   ```bash
   docker compose config
   ```

### Сборка и запуск

После настройки переменных окружения выполните:

```bash
docker compose up --build -d
```

В текущей конфигурации Compose предусмотрены следующие сервисы:

| Сервис | Назначение |
|---|---|
| `cd-app` | Django-приложение |
| `cd-db` | PostgreSQL |
| `cd-redis` | Redis |
| `cd-celery` | Фоновый обработчик Celery |

Приложение использует порт **8000** для веб-сервера. Порт **8001** предусмотрен для ASGI-сервера в production-режиме. Фактический режим запуска определяется переменной `DJANGO_DEBUG` в окружении.

Посмотреть состояние контейнеров:

```bash
docker compose ps
```

Посмотреть логи приложения:

```bash
docker compose logs -f cd-app
```

После успешного запуска откройте:

- http://localhost:8000/

### Создание администратора

Чтобы создать учётную запись администратора Django:

```bash
docker compose exec cd-app python manage.py createsuperuser
```

Административная панель в текущей конфигурации подключена по адресу:

```text
http://localhost:8000/developer_management/
```

## Локальный запуск

Для запуска без Docker потребуются Python 3.12, доступная база данных и Redis, настроенные в соответствии с параметрами проекта.

Перейдите в каталог приложения:

```bash
cd src
```

Создайте и активируйте виртуальное окружение:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```bash
pip install -r ../requirements.txt
```

Настройте переменные окружения и параметры подключения к базе данных. Затем выполните миграции:

```bash
python manage.py migrate
```

Запустите сервер разработки:

```bash
python manage.py runserver
```

Сервер разработки будет доступен по адресу http://127.0.0.1:8000/.

> Локальный запуск требует предварительной настройки базы данных, Redis и обязательных параметров Django. Одной установки Python-зависимостей недостаточно.

## Полезные команды

При работе через Docker Compose доступны следующие команды:

| Команда | Действие |
|---|---|
| `docker compose up -d` | Запустить сервисы |
| `docker compose up --build -d` | Пересобрать образы и запустить сервисы |
| `docker compose stop` | Остановить сервисы |
| `docker compose restart` | Перезапустить сервисы |
| `docker compose logs -f cd-app` | Смотреть логи приложения |
| `docker compose exec cd-app bash` | Открыть оболочку контейнера приложения |
| `docker compose exec cd-app python manage.py migrate` | Применить миграции |
| `docker compose exec cd-app python manage.py makemigrations` | Создать миграции |
| `docker compose exec cd-app python manage.py test` | Запустить тесты Django |
| `docker compose down` | Остановить и удалить контейнеры и сеть |

Команда `docker compose down -v` дополнительно удаляет тома с данными PostgreSQL и Redis. Используйте её только если действительно хотите удалить сохранённые данные.

## Безопасность

Перед развёртыванием проекта на сервере необходимо выполнить проверку конфигурации и репозитория.

- Сгенерировать новые значения для `SECRET_KEY`, паролей БД, API-токенов и ключей интеграций.
- Хранить секреты только в переменных окружения или защищённом хранилище секретов.
- Не публиковать файлы `.env`, резервные копии баз данных, приватные ключи, логи с персональными данными и дампы.
- Настроить `DEBUG=False`, допустимые хосты, CSRF и CORS для конкретного домена.
- Проверить права доступа к административной панели, API и загружаемым файлам.
- Перед production-развёртыванием проверить настройки HTTPS, cookies, резервного копирования и журналирования.

**Важно для текущего репозитория:** в истории и файлах проекта обнаружены признаки наличия чувствительных данных. Простого удаления таких значений из последнего коммита недостаточно: опубликованные пароли и ключи нужно считать скомпрометированными, заменить у соответствующих сервисов и удалить из Git-истории. Также перед открытым распространением репозитория следует проверить резервные копии БД, дампы, логи и загруженные файлы на наличие пользовательских данных.

## Статус проекта

SerCMS развивается как модульная платформа. Архитектура позволяет добавлять и дорабатывать отдельные направления без необходимости переносить всю функциональность в одно приложение.

Перед использованием в production рекомендуется провести аудит безопасности, проверить конфигурацию окружения, актуальность зависимостей и покрытие ключевых пользовательских сценариев автоматическими тестами.
